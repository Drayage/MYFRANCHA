# 🏷️ 프차야 — 프랜차이즈 상표 분쟁 카드게임

> "상표가 실제로 이동하며 뺏기는, 5라운드 기반 실시간 카드 전략 게임"

두 공동 창업자 **갑(A)** / **을(B)** 이 프랜차이즈 브랜드(상표 3개)를 두고 상표권을
쟁탈하는 1:1 카드 전략 게임입니다. 이 게임의 핵심은 점수가 아니라 **상표가 실제로
이동하며 뺏기는 시각적 전쟁**입니다 — 모든 소유권 변경은 곡선 이동·착지 바운스·충돌
흔들림 애니메이션으로 표현됩니다.

## 🎮 플레이 모드
- 🤖 **AI 대전** — 휴리스틱 AI와 대결(진영은 매판 랜덤 배정). 게임 종료 시 갑/을이 아니라
  **"승리했습니다! / 패배했습니다…"** 로 내 기준 결과를 보여줍니다.
- 👥 **로컬 패스앤플레이** — 한 기기에서 번갈아(가림막 화면 제공). 둘 다 실제 플레이어라
  결과는 그대로 "갑(A)/을(B) 승리"로 표시됩니다.
- 🌐 **온라인 대전** — Firebase Realtime DB로 방 코드 기반 매칭(호스트가 방 만들기 →
  코드를 상대에게 전달 → 상대가 방 참가). 자세한 구조는 아래 "온라인 대전" 참고.

## ✨ 옵션 (시작 화면 토글)
- 📖 **튜토리얼 켜기** — 켜면 게임 시작 시 코치마크 가이드 노출(기본 꺼짐)
- 🧬 **상표 능력 모드** — 기본 3상표(쉬어유·빨리바게뜨·남스터치)의 능력 활성
- 🌏 **상표전국시대 확장** — 상표 풀에서 랜덤 3개(능력 포함). 룰을 바꾸는 상표(덜빙=4개 올킬,
  김밥전구=무한 지구전)는 낮은 확률로 가끔 등장. 상표를 클릭하면 능력을 카드형 말풍선으로 확인.
- 🎭 **연극모드** — 카드 발동 시 갑/을이 유쾌한 대사를 주고받음

> 능력은 해당 상표를 소유했을 때 발동하며, 발동 시 토스트 + 상표 마커 강조로 표시됩니다.
> AI 대전에서는 사람이 매 판 갑/을 중 랜덤 배정됩니다(선공은 항상 갑). AI는 판마다 성향이 달라
> 패턴이 잘 읽히지 않습니다. 룰을 바꾸는 상표(덜빙·김밥전구)가 보드에 등장하면 게임 시작 전
> 모두에게 토스트로 안내됩니다.

### 🧬 능력 하이라이트
- **화남돼지집** — 라운드 시작마다(1R부터, 중앙에 있어도) 대상 지정을 1회 막는 보호막 생성.
  카드 좌상단이 아니라 상표 토큰 자체에 방패 뱃지로 표시.
- **맹한커피** — 공격받으면 뒷면 카드 2장 중 하나를 골라 성공/실패를 확인하는 미니게임으로
  50% 확률을 시각화(공격자·수비자 모두 같은 연출을 봄).
- **던진도너츠** — 소송뭉개기 대신 상대의 같은 턴 카드 효과를 그대로 복사. 원래 카드는
  무효화되지 않고 정상 발동.
- **아삭토스트** — 내 카드가 무효화되는 순간, "무효" 도장이 "유효"(초록)로 뒤집히며 정상 발동
  (라운드 중 능력을 얻어도 그 시점부터 적용).
- **저명상표 주장** — 능력 모드에서 라운드1 시작 전, 을이 상표 1개를 지정하면 갑은 1R 1차에
  그 상표를 출원으로 가져올 수 없음(1회성).
- **김밥전구** — 라운드 중간에 상표를 모두 모아도 즉시 승리하지 않고, 라운드가 끝나는
  시점에 여전히 모두 갖고 있어야 승리.

## 🆕 추가 기능
- 🃏 **세트 동시 공개** — 이번 세트 카드를 뒷면으로 깔고 한꺼번에 뒤집어 공개한 뒤, 턴 순서대로
  결과를 순차 처리. 소송뭉개기는 **같은 턴 상대 카드**를 자동 무효화("무효" 스탬프).
- 📖 **초보자 온보딩** — 튜토리얼 코치마크, 카드 툴팁, 유효 대상 하이라이트, 단계 배너, 규칙 도움말
- ▶ **리플레이** — 한 판의 모든 이동을 애니메이션과 함께 재생(재생/일시정지/스텝/속도)
- 🔊 **배경음/효과음** — Web Audio API로 그 자리에서 생성하는 마림바풍 BGM 루프 +
  카드 선택/제출/공개/이동/충돌/무효화/토큰 획득/능력 발동/승패 효과음(외부 오디오 파일 없음,
  완전 오프라인 동작). 시작 화면·게임 화면의 🔊 버튼으로 언제든 끄고 켤 수 있고,
  설정은 `localStorage`에 저장됩니다.

## 📐 규칙 요약
- **승리**: 상표 3개 모두 소유 시 즉시 승리. 5라운드 종료 시 상표가 더 많은 쪽 승리
  (동점 → 라운드 토큰 많은 쪽 → 완전 동점이면 마지막 토큰 보유자).
- **한 라운드 = 3세트**: 1차(1장) → 2차(2장) → 3차(2장). **각 세트 종료마다 선플레이어
  토큰 교대**(라운드당 3번).
- **라운드 토큰**: 한 라운드 중 상표 2개를 먼저 확보하면 1개 획득(누적).
- **카드 4종**: 출원(중앙→내 영역) / 사실관계증명(상대→내 영역) /
  불사용취소심판(상대→중앙) / 소송뭉개기(같은 턴 상대 카드 무효).
- **손패**: 매 라운드 고정 5장 — 출원 2 / 사실관계증명 1 / 불사용취소심판 1 / 소송뭉개기 1.

## 🌐 온라인 대전 (Firebase)
`js/firebase-config.js`에 실제 Firebase 프로젝트(frenzy-49857) 키가 연결되어 있습니다. 이
프로젝트는 **다른 게임과 함께 쓰는 공유 Firebase 프로젝트**이고, 실제 Realtime Database
보안 규칙은 `games/` 경로만 열려 있습니다:
```json
{ "rules": { "games": { ".read": true, ".write": true } } }
```
그래서 이 앱의 모든 읽기/쓰기는 그 안에 다시 이 앱 전용 네임스페이스를 둬서
`games/myfrancha/rooms/...` 로만 이뤄집니다(`DB_NAMESPACE = 'games/myfrancha'`,
`js/online.js`의 `roomPath()` 헬퍼가 강제). 다른 게임의 데이터와 섞이지 않도록 새 코드를
추가할 때도 이 네임스페이스를 벗어나지 마세요.

### 동작 방식 — 호스트 권위 모델
방을 만든 사람(호스트)이 `engine.js`의 게임 루프를 로컬에서 그대로 돌립니다(오프라인과 동일한
코드 경로). 다른 점은 상대(게스트) 차례의 카드/대상 선택을 AI 대신 Firebase 왕복 요청으로
받는다는 것뿐입니다(`engine.js`의 `isRemote` 분기). 게스트는 별도 엔진 없이, 동기화되는
`state` 스냅샷을 그대로 화면에 그리는 얇은 클라이언트이고, 자기 차례엔 오프라인과 같은
`ui.selectCards`/`selectTrademark`/`selectRenownedClaim` 화면으로 입력을 받아 응답만
돌려줍니다 — 그래서 게스트가 보는 카드 선택 UI는 로컬/AI 모드와 완전히 동일합니다.

호스트가 이동/무효화/라운드토큰 이벤트를 낼 때마다 `games/myfrancha/rooms/{id}/events`에도
같은 이벤트를 이어붙입니다(`onChildAdded` 구독). 게스트는 보드를 최초 1회만 그리고, 이후
상표 이동은 이 이벤트를 받아 호스트와 동일한 `animation.move()`로 재현합니다 — 그래서
곡선 이동·충돌 연출을 게스트도 그대로 봅니다. 같은 이벤트로 게스트도 자기만의 리플레이
기록을 만들어서, 게임이 끝나면 게스트 쪽 "▶ 리플레이 보기"도 정상 동작합니다.

맹한커피 복불복 미니게임 결과(blocked)도 이벤트로 흘려보내, 게스트 화면엔 관전용 버전
(`ui.playCoffeeGambleSpectator`)으로 재현됩니다 — 다만 호스트 쪽 애니메이션이 끝난 뒤에야
결과를 알 수 있어 게스트 화면에 몇 초 늦게 뜹니다. 화남돼지집 보호막 배지·저명상표 리본은
`trademarks[].shielded`/`renownedClaim`처럼 state 자체로 유도 가능해서 별도 이벤트 없이
매 상태 스냅샷마다 `ui.syncTrademarkMarkers()`로 다시 맞춰줍니다.

알려진 범위 제한:
- 호스트가 나가면 방 상태가 `abandoned`로 표시되어 게스트에게 토스트로 안내됩니다. 다만
  게스트가 나갈 때는 별도 안내를 남기지 않습니다.
- 새로고침 시: 호스트는 기존 "🔄 이어하기"로 자동 복구되고, 게스트는 시작 화면의
  "🌐 온라인 방 재접속" 버튼으로 같은 방에 다시 들어갑니다(재접속 시 지난 이동은 이미
  최신 상태 스냅샷에 반영되어 있으므로 다시 애니메이션하지 않고, 그 시점 이후 이동만 재생).

`state`(onValue)와 `request`(onValue)는 서로 다른 경로라 도착 순서가 보장되지 않는다 —
특히 재접속 직후 이미 대기 중인 request가 아직 안 그려진 보드보다 먼저 오면 대상 선택 UI가
엘리먼트를 못 찾아 Promise가 영원히 안 풀리고 게스트 화면이 멈출 수 있었다. 게스트의 request
핸들러는 이제 보드가 준비될 때까지 대기하고, "세대 번호"로 자신보다 최신 요청이 이미 왔으면
그 요청엔 답하지 않는다(호스트 새로고침 후 재요청 등으로 request가 덮어써지는 경우 대비).

`js/online.js`는 `createRoom` / `joinRoom` / `subscribeRoom` / `requestFromGuest` /
`subscribeRequest` / `answerRequest` / `pushState` / `pushEvent` / `subscribeEvents` /
`markAbandoned` 등을 제공합니다.
